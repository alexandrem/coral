# Coral Configuration Reference

Use this reference to look up a setting's name, expected value, and default
after choosing a workflow in [configuration and remote access](configuration.md).
Keep settings in the file belonging to their component: the same section name
can mean collection on an agent and polling or retention on a Colony.

| Settings for… | Reference section |
| --- | --- |
| File locations and precedence | [Configuration files](#configuration-files) |
| CLI defaults, Discovery, and AI | [Global configuration](#global-configuration) |
| Colony identity, networking, and central retention | [Colony configuration](#colony-configuration) |
| Project selection and storage | [Project configuration](#project-configuration) |
| Agent enrollment, observation, and local retention | [Agent configuration](#agent-configuration) |
| Agent environment overrides | [Environment variables](#environment-variables) |

The tables distinguish settings generated by `init`, startup defaults, and
values you must supply. Fields described as reserved or unimplemented do not
enable a feature. After editing startup settings, restart the affected component
and verify its behavior as described in [Colony operations](colony-operations.md)
or [agent configuration](configuration.md#configure-an-agent). Command syntax
lives in the single [CLI manual](../CLI_REFERENCE.md).

Duration fields use Go duration strings such as `30s`, `5m`, and `168h`.
Use `168h` for seven days in YAML duration fields; `7d` is not accepted by the
standard duration parser. Retention fields explicitly suffixed `_days` or
`_hours` instead take integer counts. Examples below are fragments to merge
into the appropriate component file.

Dots in field names indicate YAML nesting: `system_metrics.interval` means
`interval` inside the `system_metrics` section. Each table belongs to the
component named in its section heading.

## Configuration Files

| Component | Location |
| --- | --- |
| Global CLI | `~/.coral/config.yaml`; with `CORAL_CONFIG=<base>`, uses `<base>/.coral/config.yaml` |
| Colony | `~/.coral/colonies/<id>/config.yaml`; system fallbacks are `/etc/coral/colonies/<id>.yaml` and a matching `/etc/coral/colony.yaml` |
| Project | `.coral/config.yaml` in the current directory |
| Agent | Explicit `--config`, otherwise `./agent.yaml`, then `/etc/coral/agent.yaml` |

Colony selection uses an explicit command option where supported, then
`CORAL_COLONY_ID`, project selection, and the global default. Agent file values
are overlaid by supported environment variables and explicit startup options.
These are separate resolution rules, not one uniform merge for every field.

## Global Configuration

| Field                           | Type     | Default                      | Description                                  |
| ------------------------------- | -------- | ---------------------------- | -------------------------------------------- |
| `version`                       | string   | `"1"`                        | Configuration schema version                 |
| `default_colony`                | string   | -                            | Default colony ID to use when not specified  |
| `discovery.endpoint` | string | `https://discovery.coralmesh.dev` | Discovery service URL |
| `discovery.timeout`             | duration | `10s`                        | Discovery request timeout                    |
| `discovery.stun_servers`        | []string | `[stun.cloudflare.com:3478]` | STUN servers for NAT traversal               |
| `ai.provider` | string | `anthropic` | Legacy provider setting; configure investigations through `ai.ask` |
| `ai.api_key_source` | string | `env` | Legacy key-source setting; use `ai.ask.api_keys` for provider references |
| `preferences.auto_update_check` | bool | `true` | Preference field; does not establish an implemented updater |
| `preferences.telemetry_enabled` | bool | `false` | Telemetry preference field |

The shipped Discovery endpoint is `https://discovery.coralmesh.dev`, with STUN
at `stun.cloudflare.com:3478`. Change it consistently across participating
components when using a self-hosted deployment.

### AI Configuration

`ai.ask` controls the local investigation client; per-Colony overrides use the
Colony file's top-level `ask` section. Implemented providers include Anthropic,
Google, OpenAI, and Ollama. See [AI assistants](ai-assistants.md) for setup
and model/provider interpretation.

| Field                                | Type     | Default    | Description                                      |
| ------------------------------------ | -------- | ---------- | ------------------------------------------------ |
| `ai.ask.default_model` | string | `anthropic:claude-sonnet-4-6` | Default model, in `provider:model-id` form |
| `ai.ask.fallback_models` | []string | Global fallback list | Models to try if the primary fails |
| `ai.ask.api_keys`                    | map      | `{}`       | API keys (use `env://VAR_NAME` format)           |
| `ai.ask.base_urls`                   | map      | `{}`       | Custom base URLs per provider (OpenAI-compatible endpoints) |
| `ai.ask.conversation.max_turns`      | int      | `10`       | Maximum conversation turns to keep               |
| `ai.ask.conversation.context_window` | int      | `8192`     | Maximum tokens for context                       |
| `ai.ask.conversation.auto_prune`     | bool     | `true`     | Auto-prune old messages when limit reached       |
| `ai.ask.agent.mode`                  | string   | `embedded` | Agent mode: `embedded`, `daemon`, or `ephemeral` |
| `ai.ask.agent.dispatch_mode`         | string   | `mcp`      | How the agent calls tools: `mcp` or `cli` (local `coral` subprocesses) |

The default fallback list is `anthropic:claude-3-5-sonnet-20241022` and
`openai:gpt-4o-mini`. Replace it with models your provider accounts can use.
Write `api_keys` values as `env://VARIABLE` to reference a key in the
environment. The OpenAI base URL is resolved from `base_urls.openai`, then
`OPENAI_BASE_URL`, then the provider default.

```yaml
# ~/.coral/config.yaml (global CLI settings)
ai:
  ask:
    default_model: anthropic:claude-sonnet-4-6
    api_keys:
      anthropic: env://ANTHROPIC_API_KEY
```

## Colony Configuration

Initialize server identity with `coral init`; do not hand-invent a CA or copy
one Colony's identity to several running coordinators.

### WireGuard Mesh Network

| Field                            | Type     | Default         | Description                                        |
| -------------------------------- | -------- | --------------- | -------------------------------------------------- |
| `wireguard.private_key`          | string   | Auto-generated  | WireGuard private key (base64)                     |
| `wireguard.public_key`           | string   | Auto-generated  | WireGuard public key (base64)                      |
| `wireguard.port`                 | int      | `41580`         | WireGuard UDP listen port                          |
| `wireguard.public_endpoints`     | []string | `[]`            | Public endpoints for agent connections (see below) |
| `wireguard.interface_name`       | string   | platform-specific           | Network interface name                             |
| `wireguard.mesh_ipv4`            | string   | `100.64.0.1`    | Colony's IPv4 address in mesh                      |
| `wireguard.mesh_network_ipv4`    | string   | `100.64.0.0/10` | IPv4 mesh subnet (CIDR)                            |
| `wireguard.mesh_ipv6`            | string   | `fd42::1`       | Colony's IPv6 address in mesh                      |
| `wireguard.mesh_network_ipv6`    | string   | `fd42::/48`     | IPv6 mesh subnet (CIDR)                            |
| `wireguard.mtu`                  | int      | `1420`          | Interface MTU (1500 - 80 overhead)                 |
| `wireguard.persistent_keepalive` | int      | `25`            | Keepalive interval in seconds                      |

Public endpoints are externally reachable UDP addresses, not mesh IPs. Leaving
`public_endpoints` unset allows startup to publish its STUN observation; setting
it supplies an override. Avoid a mesh subnet that overlaps an existing route.
See [network paths](deployment.md#network-paths) for reachability limits.

### Remote Colony Connection

| Field                               | Type   | Default | Description                                                      |
| ----------------------------------- | ------ | ------- | ---------------------------------------------------------------- |
| `remote.endpoint`                   | string | -       | Remote colony's public HTTPS endpoint URL                        |
| `remote.certificate_authority`      | string | -       | Path to CA certificate file for TLS verification                 |
| `remote.certificate_authority_data` | string | -       | Base64-encoded CA certificate (takes precedence)                 |
| `remote.insecure_skip_tls_verify`   | bool   | `false` | Skip TLS verification (testing only, never in prod)              |
| `remote.ca_fingerprint.algorithm`   | string | -       | CA fingerprint hash algorithm (e.g., `sha256`)                   |
| `remote.ca_fingerprint.value`       | string | -       | Hex-encoded CA fingerprint for continuous verification (RFD 085) |

Operator tokens are supplied through `CORAL_API_TOKEN`; `remote` has no
`api_token` field. TLS data takes precedence over a CA file. Fingerprint
verification applies when configured; `insecure_skip_tls_verify` disables
verification and belongs only in isolated tests.

## Agent Configuration

Agent defaults enable automatic process observation, telemetry, host metrics,
and eligible continuous profilers. Collection still requires a visible process,
platform support, and the runtime-specific endpoints used by each profiler.

Use `--no-monitor-all` to override automatic observation at startup. Process
observation and collector disable switches are independent.

Agent fields are grouped below by subsystem:
[service watches](#service-watches), [telemetry](#telemetry-collection),
[enrollment](#additional-bootstrap-settings), [Beyla](#beyla-integration-configuration),
[debugging](#debug-configuration), [host metrics](#system-metrics-configuration),
[CPU profiling](#continuous-cpu-profiling-configuration), and
[memory profiling](#continuous-memory-profiling-configuration).

### Runtime and Process Observation

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `agent.runtime` | string | `auto` | Runtime environment: `auto`, `native`, `docker`, `kubernetes` |
| `agent.colony.id` | string | - | Colony ID to connect to |

| `agent.monitor_all` | bool | `true` | Automatically observe processes; use `false` for explicit watches only |

| Field | Type | Default | Description |
| --------------------- | ---------- | ----------- | ------------------------------------------------- |
